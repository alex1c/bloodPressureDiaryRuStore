1. Разработчик и контакты

Приложение разработано и публикуется индивидуальным разработчиком. Контакт по вопросам конфиденциальности и поддержки: rustore-alex1c@yandex.ru.

Этот документ описывает обработку данных приложением и необязательными сторонними SDK. Он не является юридической консультацией и не создаёт гарантий сверх прямо изложенного.

2. Назначение приложения

«Дневник давления» помогает вести личный дневник артериального давления, пульса, лекарств и связанных показателей, которые вы вводите сами. Это потребительский дневник. Приложение не является медицинским изделием, не ставит диагнозы и не заменяет консультацию врача.

3. Медицинские записи, которые хранятся локально

На устройстве вы можете хранить, в частности:

  • давление (систолическое / диастолическое) и пульс;
  • заметки и теги к измерениям;
  • дополнительные показатели (например вес, глюкозу, SpO₂, температуру);
  • лекарства, расписания и отметки приёма;
  • отображаемые имена семейных профилей;
  • язык интерфейса и локальные настройки напоминаний.

Эти данные дневника вводятся вами и предназначены для использования на устройстве.

4. Нет аккаунта и нет облачного дневника разработчика

Приложение не требует учётной записи пользователя. У разработчика нет сервера синхронизации дневника и нет центральной базы ваших измерений.

5. Локальная SQLite и экспорт PDF/JSON

Основные данные дневника хранятся в локальной базе SQLite в песочнице приложения. Android Auto Backup для данных приложения отключён, поэтому дневник не предназначен для автоматической выгрузки в облачный бэкап Google.

Вы можете создать JSON-резервную копию или PDF-отчёт для врача на устройстве. Эти файлы покидают устройство только если вы явно отправляете их через системный Share Sheet или аналогичный интерфейс. Разработчик не получает эти файлы автоматически. Вы несёте ответственность за выбранный адресат.

6. Yandex Mobile Ads

Если вы разрешаете рекламу, приложение использует Yandex Mobile Ads для показа баннеров и эпизодической межстраничной рекламы. Рекламные блоки для RuStore и Google Play настроены раздельно. Google AdMob в этом релизе не используется.

Согласно документации Yandex Mobile Ads для Google Play Data Safety, SDK может обрабатывать идентификаторы устройства и иные ID (включая Advertising ID при наличии разрешения) в целях рекламы и маркетинга и шифрует указанные данные при передаче по HTTPS/TLS. По умолчанию в руководствах вендора содержимое дневника здоровья не относится к данным, собираемым Ads SDK. См. актуальный Data Safety guide Yandex для Mobile Ads.

Реклама не показывается поверх критичных экранов ввода измерений и системных диалогов разрешений. Отдельного гарантированного режима «только неперсонализированная реклама» интеграция не предоставляет: отказ от рекламы блокирует рекламные запросы.

7. AppMetrica (аналитика)

Если вы разрешаете техническую аналитику, приложение использует Yandex AppMetrica для измерения использования приложения. Код приложения отправляет только события из разрешённого списка (например открытие «Графиков» или коды смены языка). Он не передаёт значения давления и пульса, названия лекарств, дозы, статусы приёма, значения показателей здоровья, заметки, теги или имена профилей.

Согласно руководству AppMetrica по Google Play Data Safety, в типовой конфигурации SDK может обрабатывать сведения о сбоях, диагностику / производительность и идентификаторы устройства (при наличии разрешения), а также шифрует указанные данные при передаче. Отслеживание геолокации в конфигурации этого приложения отключено (нет пути GPS / приблизительной геолокации через AppMetrica). Сетевой трафик SDK может использовать обычные IP-адреса; приложение не включает vendor API «location tracking» и location-consent рекламного SDK. Точный набор категорий зависит от поставленной сборки SDK и документации вендора.

8. Рекламный идентификатор и сведения об устройстве

При разрешении необязательных SDK они могут обрабатывать технические сведения об устройстве и Google Advertising ID (GAID) с учётом настроек Android (в том числе персонализации рекламы / сброса ID). Код TypeScript приложения не читает Advertising ID напрямую; Ads SDK объявляет разрешение AD_ID, как указано в документации Yandex для SDK 4.5.0+.

9. Правовые основания обработки

В зависимости от вашего региона обработка может опираться на:

  • согласие — для необязательных SDK рекламы и/или аналитики;
  • законные интересы или необходимость исполнения запроса — для локальных функций дневника на устройстве (где применимо);
  • иные основания, требуемые применимым правом.

Раздел носит информационный характер и не утверждает полное соответствие всем правовым режимам мира одним только этим документом.

10. Согласие, отказ и отзыв

При запуске (и повторно в Настройках) вы можете независимо разрешить или отклонить техническую аналитику (AppMetrica) и рекламу (Yandex Mobile Ads). Основные функции дневника остаются доступны при отказе.

Выбор по необязательным SDK применяется после подтверждения в приложении для текущей сессии. Позже его можно изменить в Настройках. Отказ и отзыв останавливают включение соответствующих путей SDK со стороны приложения; уже переданные технические данные у Яндекса продолжают обрабатываться по правилам Яндекса.

Для Yandex Mobile Ads решение по рекламе передаётся через API setUserConsent (документация Yandex по GDPR); инициализация рекламы не вызывается, пока реклама не разрешена. Для AppMetrica активация и отправка событий зависят от разрешения аналитики в коде приложения.

Внутриигровой диалог — это собственный экран целей для SDK Яндекса. Это не сертифицированный Google CMP / инструмент IAB TCF. Требования Google к сертифицированной CMP для рекламного спроса Google относятся к случаям использования AdMob / спроса Google; в этом релизе AdMob не поставляется.

11. Международная передача данных

Приложение распространяется международно (в том числе через закрытое тестирование Google Play). Если вы включаете необязательные SDK Яндекса, связанные технические данные могут обрабатываться Яндексом согласно условиям и политикам Яндекса, что может включать обработку за пределами страны вашего проживания.

В политике не указываются вымышленные страны размещения серверов, SCC или данные представителя в ЕС. См. опубликованные условия Яндекса для AppMetrica и Mobile Ads.

12. Сроки хранения

Локальные данные дневника остаются на устройстве, пока вы не удалите записи или не удалите приложение.

Технические данные SDK Яндекса (если включены) хранятся по правилам и настройкам продуктов Яндекса. У разработчика нет отдельного серверного графика хранения этих данных и нет оснований указывать единый фиксированный срок для всех систем Яндекса.

13. Права пользователей и обращения

В зависимости от применимого права (например GDPR / UK GDPR, где они действуют) у вас могут быть права на доступ, исправление, удаление, ограничение или возражение против определённой обработки, а также право подать жалобу в надзорный орган.

Локальный дневник можно править и удалять в приложении. Чтобы запросить удаление технических данных, которые необязательные SDK могли обработать после вашего разрешения, напишите на rustore-alex1c@yandex.ru (запросы о конфиденциальности). Мы ответим и при необходимости укажем опубликованные каналы Яндекса. Удаление локального дневника в приложении отдельно от записей сторонних SDK.

14. Удаление данных и границы контроля разработчика

Вы можете удалять отдельные измерения, показатели, лекарства, напоминания и профили (с сохранением хотя бы одного профиля) или удалить приложение, чтобы очистить локальное хранилище.

Запросы на удаление собранных технических данных принимаются по адресу rustore-alex1c@yandex.ru. Разработчик не может самостоятельно стереть технические данные, уже хранящиеся у Yandex Mobile Ads или AppMetrica, и не ведёт сервер с вашим дневником здоровья. Эти сервисы следуют собственным правилам удаления и хранения.

15. Защита данных

Локальный дневник находится в песочнице приложения. Трафик необязательных SDK использует шифрование, описанное вендорами (например HTTPS/TLS для раскрытий Data Safety Mobile Ads; AppMetrica документирует шифрование при передаче для указанных типов данных). Ни одна мера не абсолютна: защищайте устройство блокировкой экрана и делитесь экспортами только с доверенными получателями.

16. Возрастные ограничения

Приложение предназначено для взрослых, ведущих личный или семейный дневник. Оно не ориентировано на детей и не рассчитано на программы Google Play Families / Designed for Families. Если вы младше возраста цифрового согласия в вашей стране, используйте приложение только с родителем или опекуном, как требует местное право.

17. Изменения политики

Политика может обновляться при изменении приложения, SDK или требований права. Дата в начале документа будет обновлена. Существенные изменения при возможности также отмечаются в карточке магазина или в приложении.
